# SKELETON.md - сборка скелета (одноразовая фаза)

Читается один раз, до первого фичевого слайса. Подчиняется `tech.md` - контракты, схема БД, стек и правила кода здесь не переопределяются, только исполняются. При нехватке контракта - тот же блок `CONTRACT GAP`, что и в `TASKS.md`.

---

## 1. CI/CD

Два раздельных пайплайна, не один общий.

**Гейт на PR** (без деплоя):
```
gofmt -l .            # пусто
templ generate --check
go vet ./...
golangci-lint run
govulncheck ./...
go test ./... -race
# миграции goose up на эфемерном Postgres (сервис в CI)
docker build .         # только сборка, без push
```

**Деплой на мёрдж в `main`** (отдельный workflow, запускается только после зелёного PR-гейта):
```
docker build && docker push
ssh <vps> "cd project && git pull && docker compose build && docker compose up -d"
docker compose exec web ./app migrate
docker compose exec web ./app collectstatic   # если применимо к static-пайплайну Tailwind
```

Ветка `main` защищена: прямые пуши запрещены, мёрдж только через PR с зелёным гейтом.

## 2. Защита общих файлов

Правки следующих путей вне осознанной архитектурной сессии - красный флаг, не фичевая работа:

- `tech.md`, `SKELETON.md`, `TASKS.md`, `CLAUDE.md`
- `internal/money/`, `internal/domain/*/types.go` (общие типы, §6 `tech.md`)
- `db/schema` / `migrations/` (миграции — отдельная осознанная правка, не побочный эффект фичи)
- `web/templates/components/` (UI-примитивы)
- `web/templates/layout.templ`

Настроить pre-commit hook (или Claude Code hook), который предупреждает при попытке правки этих путей внутри ветки `feat/*`, если задача в `TASKS.md` явно не называет эти файлы в списке затрагиваемых.

## 3. Порядок сборки скелета

1. `git init`, `go.mod`, структура папок из §3 `tech.md`, `cmd/app/main.go` с graceful shutdown (подкоманды `serve|migrate|seed|admin-password`, ещё без реализации).
2. CI из раздела 1 этого файла, зелёный на пустом коммите. `main` защищена.
3. `docker/compose.yml`: `app`, `postgres`, `caddy`. Профиль `dev` дополнительно `tailwind --watch`, `templ generate --watch`. Поднимается одной командой.
4. Миграции `goose` из схемы §4 `tech.md` - пишутся вручную по этой схеме (в отличие от Drizzle/Prisma миграции здесь не генерируются автоматически из Go-структур, схема в `tech.md` - источник истины, SQL в `migrations/` - её точное отражение). `app seed` наполняет БД: 3 товара с размерами, ценами, изображениями-заглушками, тестовые визиты/события/заказы за 30 дней.
5. `internal/config` - чтение env, валидация на старте, падение при отсутствии обязательного значения. `.env.example` из §10.2 `tech.md`.
6. Layout, навигация, полная цепочка middleware: `request_id → recover → logging → securityheaders → csrf → attribution → ratelimit`.
7. UI-примитивы из §7.2 `tech.md` - все, с сигнатурами из этого раздела. Отрендерить в служебном роуте `/dev/kitchen-sink` (не деплоится в прод, скрыт за `APP_ENV=dev`).
8. Фейковые клиенты `internal/payments/nowpayments.Fake` и `internal/telegram.Fake` за интерфейсами из §5.4-5.5 `tech.md` - приложение полностью работоспособно без единого внешнего ключа (`PAYMENTS_PROVIDER=fake`, `TELEGRAM_PROVIDER=fake`).
9. Admin-аутентификация (§8.5 `tech.md`) и middleware `adminauth`, один админ создаётся через `app admin-password`.
10. Воркер outbox запущен, обрабатывает демо-уведомление на фейковом провайдере.
11. **Эталонная вертикаль**: полный end-to-end путь главная → добавление в корзину → фрагмент корзины, с тестами по доктрине §11 `tech.md`. Мёрджится в `main` последним шагом скелета. Все последующие слайсы в `TASKS.md` копируют её структуру (домен → репозиторий → хендлер → шаблон → тест).

- схема БД целиком (§4) и общие типы (§6)

## 5. Long-lead задачи (запускать в день один, параллельно разработке)

Эти шаги имеют внешнюю задержку (модерация, DNS, KYC) и не блокируются на готовности кода:

- регистрация домена;
- аренда VPS (минимум 2 CPU / 2GB RAM под app + postgres + caddy);
- регистрация аккаунта NOWPayments, получение API-ключа и IPN-секрета (может требовать верификации);
- создание бота через `@BotFather`, получение токена, резервирование username;
- DNS A-запись на IP сервера - завести сразу после аренды VPS, чтобы к моменту деплоя (S8 в `tech.md`) пропагация уже прошла.

---

## 6. Реальное время

Отдельного транспорта реального времени (WebSocket/SSE) в проекте нет и не закладывается в скелет: статус заказа на `/order/{token}` обновляется поллингом раз в 10 секунд (§7.1 `tech.md`), обновление стока в админке - обычная перезагрузка страницы/фрагмента по HTMX-паттерну §5.3. Если в будущем появится реальная потребность в push-обновлениях - это `CONTRACT GAP`, не тихое добавление в фичевой сессии.
